## dms-v4-bmad-v6

Disaster Response Management System — multi-role (coordinator/assessor/responder/donor) incident, assessment, fulfillment, and delivery tracking. Next.js 14 App Router single app (pages in `src/app/(auth)/*`, API in `src/app/api/v1/*`), Prisma 6 + PostgreSQL, Zustand + react-query, Dexie offline sync, next-pwa. Planning artifacts: `_bmad-output/planning-artifacts/`. `docs/architecture.md` is partially stale — trust the code.

## Policy

- Never point test suites at `drms_dev`; API and baseline-E2E suites run only against `drms_test` (guards in `tests/setup-api.ts` and `tests/e2e-baseline/global-setup.ts` refuse otherwise, and E2E setup truncates it).
- Never hand-edit `public/sw.js` or `public/workbox-*.js` — generated by next-pwa (`pwa.config.js`).

## Where things are

- Shared Prisma client: `src/lib/db/client.ts` (`import { db } from '@/lib/db/client'`) — no `lib/prisma.ts` exists.
- Business logic: `src/lib/services/*.service.ts`; zod schemas: `src/lib/validation/<domain>.ts`.
- Offline stack: Dexie in `src/lib/db/offline.ts`; sync queue/engine/conflict in `src/lib/sync/`.
- Regression-baseline contract + pinned known defects: `_bmad-output/test-artifacts/automation-summary.md`.

## Running and verifying

- Use npm/npx for everything — all wired tooling (Playwright webServers, chained scripts, verify-baseline.sh) invokes npm even though `packageManager` declares pnpm.
- `docker compose up -d` first: Postgres on **5435** (not 5432), MinIO 9100/9101.
- After schema changes, reset the test DB: `npm run db:push:test` (drms_test only).
- Pre-merge gate: `npm run test:baseline:all` — unit (jsdom), API+services (real drms_test, runInBand), Playwright golden journeys (own server on :3100, forced drms_test).
- Touching severity/gap analysis? Run the full baseline — that pipeline has 4+ fix commits and pinned semantics.

## Conventions that differ from defaults

- New API endpoints go under `/api/v1/**`; wrap handlers in `withAuth()` (re-reads roles from DB) — never parse the Authorization header yourself.
- Respond only via `@/lib/api/response` helpers (`successResponse`/`errorResponse`/`handleApiError`); never hand-build `{data, meta}` (`src/app/api/v1/responses/assigned/route.ts` is the anti-pattern).
- Role checks are manual `context.roles.includes(...)` inside handlers — no decorator exists.
- Never `new PrismaClient()` — use the shared client; 4 legacy violations exist, add no fifth.
- Severity is config-driven via `gapFieldSeverityService` — never hardcode thresholds; its 30s cache self-invalidates, don't add parallel caches.
- Frontend server calls go through `apiGet`/`apiPost` (`src/lib/api.ts`); react-query (`src/hooks/use*.ts`) for server state, Zustand (`src/stores/`) for client/UI state only.
- Offline mutations enqueue via `SyncQueueManager.addItem` (`src/lib/sync/queue.ts`) — never write Dexie tables directly.
- Currency symbol comes from `getCurrencyConfig()` (`src/lib/currency.ts`) — never hardcode ₦.

## Known pitfalls

- `tests/setup.ts` mocks `@prisma/client` with only `PrismaClient` — unit suites needing Prisma enums must re-register the mock including the enums.
- `tests/e2e/**`, `tests/smoke/**`, `tests/legacy-backup/**` are quarantined legacy — not the baseline; don't repair them or treat their failures as regressions.
- Characterization tests pin known defects on purpose (list in automation-summary.md, Phase 1) — a fix must flip its test in the same change.
- `next/jest` on Windows force-prepends `/node_modules/` to `transformIgnorePatterns`; both jest configs overwrite it after resolution — don't remove the override.
- `prisma/dev.db`, `schema-backup-*.prisma`, `schema-minimal.prisma` are SQLite-era leftovers — ignore them.
